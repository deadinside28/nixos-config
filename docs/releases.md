# Выпуски Pixel DE (раздел 15 роадмапа)

## Каналы

- **Рабочий** — коммит, на котором система сейчас собрана и проверена. Помечается тегом `stable-YYYY-MM-DD`.
- **Кандидат** — ветка с изменениями и, возможно, новым `flake.lock`. На основную ветку попадает только после проверки по списку ниже.

Выпуск связывает исходники, `flake.lock` и версии схем данных:

| Данные | Версия схемы | Где |
|---|---|---|
| `system.json` | `schemaVersion` (сейчас 1) | `modules/system/gui-settings.nix` |
| настройки оболочки `settings.json` | `schemaVersion` (сейчас 1), миграции в `Settings.migrate()` | `modules/shell/qml/common/Settings.qml` |
| события календаря `events.json` | `schemaVersion` (сейчас 1) | `modules/shell/qml/services/Calendar.qml` |
| заметки | обычные Markdown-файлы, схемы нет | — |

Когда схема меняется, номер растёт, и в коммите описывается миграция. Старая версия оболочки, увидев файл новее себя, не пишет в него. Для `system.json` это проверка при сборке, для календаря — блокировка правок.

## Перед выпуском

1. `nix flake check` — вычисление конфигурации и проверки: файловые операции, «Память», магазин, календарь, напоминания, портал на настоящей шине и `shell-load` (настоящий Quickshell под headless sway открывает все окна и страницы настроек; любая ошибка QML роняет проверку).
2. `pixel-rebuild build` — полная сборка без активации. Успешная сборка не заменяет проверку в работе.
3. `pixel-metrics` — метрики после входа и в простое, для сравнения с прошлым выпуском (раздел 14). Файл сохраняется в `~/.local/state/pixel-shell/metrics/`.
4. Активация (`switch`). Предыдущее поколение остаётся для отката: «Настройки → Система → Откат» или пункт загрузчика.
5. Пройти сценарии ниже. Пока они не пройдены, старые поколения не удаляются.

`nixos-rebuild test` не песочница: он активирует конфигурацию в текущей системе и может перезапускать службы, но не проверяет новое ядро без перезагрузки. В VM можно проверить сборку и часть сценариев; графику, сон и мониторы — только на железе.

## Сценарии (15.4)

| Область | Проверка | Результат |
|---|---|---|
| Сессия | вход, выход, повторный вход; `systemctl --user restart pixel-shell` | |
| Обновление | `switch` из «Настроек»: панель перезапускается, задача доходит до «Готово» | |
| Мониторы | отключение и подключение второго экрана, масштаб, окна не теряются | |
| Питание | блокировка; сон из меню, по `systemctl suspend` и крышке/кнопке — сначала блокировка; андервольт после пробуждения (`journalctl -u ryzen-undervolt`) | |
| Окна | смена режима (Super+Shift+Пробел), диалоги остаются плавающими, полноэкранная игра, XWayland, Wine | |
| Звук и сеть | смена устройства, перезапуск PipeWire и NetworkManager | |
| Файлы | копирование с ошибкой, распаковка в папку без прав, большие каталоги | |
| Порталы | открыть и сохранить из GTK4, Qt, Chrome, Flatpak (`docs/filechooser.md`); захват экрана | |
| Приложения | установка и удаление в «Магазине» (Nix и Flatpak), сбой установки, очистка кеша и сброс данных в «Памяти» | |
| Данные | заметки и события сохраняются, напоминание приходит после перезапуска оболочки | |

## Безопасность и обновления входов

- Установка пакета через «Магазин» не обновляет `flake.lock`. Обновление входов — отдельное действие («Магазин → Обновления → Обновить систему») и проходит тот же список.
- Обновления безопасности идут тем же путём. Цель — не заморозить всё навсегда, а не выпускать непроверенное.
- Обращения к Hyprland собраны в генераторах `HyprConf.qml` и `WindowModes.qml`, а также в Lua-файлах `modules/hyprland`. При обновлении Hyprland сверять изменения Lua API с ними.
- Quickshell и его Qt берутся из одного nixpkgs. Не закреплять их отдельно, чтобы не получить несовместимую смесь библиотек.
